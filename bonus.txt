Bonus: Comprehensive Logging System with Configuration File
============================================================

Implementation Overview:
------------------------
We implemented a comprehensive, thread-safe logging system (Logger class) that provides extensive debugging and monitoring capabilities for the tanks game simulation. This system goes beyond basic logging requirements and includes advanced features for production-ready applications.

Key Features:
-------------
1. **Multi-Level Logging**: Supports DEBUG, INFO, WARN, ERROR, and OFF log levels with configurable filtering
2. **Thread-Safe Operation**: Uses mutex-based synchronization to prevent race conditions in multi-threaded environments
3. **Configurable Output**: Supports both console and file output with independent control
4. **External Configuration**: Uses configuration files (logging.conf, logging_debug.conf, logging_production.conf) for runtime behavior control
5. **Timestamp Support**: Includes millisecond-precision timestamps for precise event tracking
6. **Thread ID Tracking**: Optional thread identification for debugging multi-threaded execution
7. **Component-Based Logging**: Supports component tags for organized log categorization
8. **Deadlock Prevention**: Implements internal/external logging separation to prevent recursive mutex locks

Configuration Files:
--------------------
- **logging.conf**: Default configuration (INFO level, console + file output)
- **logging_debug.conf**: Debug configuration (DEBUG level, all features enabled, thread IDs)
- **logging_production.conf**: Production configuration (ERROR level only, file output only)

Configuration format example:
```
LOG_LEVEL=INFO
LOG_FILE=tanks_game.log
CONSOLE_OUTPUT=true
TIMESTAMP=true
THREAD_ID=false
```

Integration Points:
-------------------
The logging system is integrated throughout the entire application:

1. **Simulator Level**: 
   - Game configuration parsing and validation
   - Map loading and validation
   - Multi-threading coordination and worker thread tracking
   - Overall simulation progress and statistics

2. **GameRunner Level**:
   - Individual game execution start/completion
   - GameManager library loading and unloading
   - Player and algorithm creation
   - Detailed game results (winner, rounds, end reason, final state)

3. **Thread Management**:
   - Worker thread creation and assignment
   - Thread ID tracking for debugging race conditions
   - Mutex acquisition and release logging
   - Task distribution and completion tracking

4. **Component Loading**:
   - Dynamic library loading (dlopen/dlclose operations)
   - Factory registration and discovery
   - Algorithm and GameManager instantiation

Usage Examples:
---------------
The system provides convenient macros for easy integration:
```cpp
LOG_DEBUG("Detailed debugging information", "COMPONENT");
LOG_INFO("General information messages", "COMPONENT");
LOG_WARN("Warning conditions", "COMPONENT");
LOG_ERROR("Error conditions", "COMPONENT");
```

Console Output Control:
-----------------------
- DEBUG messages are written ONLY to log files (never to console)
- INFO messages appear on stdout when console output is enabled
- WARN and ERROR messages appear on stderr when console output is enabled
- This separation ensures clean console output while maintaining detailed file logs

--------------
1. **Build and run any simulation mode**:
   ```bash

   ./simulator_318772340_206580102 -map map1.txt -gameManagers GameManagers/ -algorithm1 Algorithms/Algorithm1.so -algorithm2 Algorithms/Algorithm2.so
   ```

2. **Check generated log file**: `tanks_game.log` (or configured filename) will contain:
   - Logger initialization and configuration details
   - Complete simulation workflow tracking
   - Thread operations and synchronization events
   - Individual game execution details
   - Component loading and registration events
   - Detailed game results and statistics

3. **Test different configurations**:
   - Copy `logging_debug.conf` to `logging.conf` for maximum detail
   - Copy `logging_production.conf` to `logging.conf` for minimal logging

4. **Multi-threading verification**: Run with multiple threads to see thread-specific logging:
   ```bash
   ./simulator_318772340_206580102 -map map1.txt -gameManagers GameManagers/ -algorithm1 Algorithms/Algorithm1.so -algorithm2 Algorithms/Algorithm2.so -threads 4
   ```

Technical Implementation:
-------------------------
- **Location**: UserCommon/Logger.h and UserCommon/Logger.cpp
- **Namespace**: UserCommon_318772340_206580102
- **Thread Safety**: std::mutex with lock_guard for all operations
- **Memory Management**: Smart pointers for file handles
- **Error Handling**: Graceful degradation when file operations fail
- **Performance**: Early return optimization for filtered log levels

This logging system demonstrates advanced C++ programming concepts including thread safety, RAII, configuration management, and production-ready error handling, making it suitable for both development debugging and production monitoring.
